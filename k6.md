# k6 API tests

The tests read `VAULT_URL` and `VAULT_TOKEN` from `test_k6/.env` using the
shared `config.js` helper. Read-focused coverage includes current KV data, per-secret version metadata,
root metadata listing, and nested metadata listing for
`infrastructure/kubernetes/000081`. The write test measures authenticated KV
secret writes using synthetic payloads.

## Build k6

```sh
go install go.k6.io/xk6@latest
xk6 build
```

## Run the API tests

Start `vault-server`, then run:

```sh
test -f test_k6/.env || cp test_k6/.env_example test_k6/.env
# Set VAULT_TOKEN in test_k6/.env to a managed token with access to the kv mount.
./k6 run --insecure-skip-tls-verify test_k6/api_v1_kv_metadata.js
./k6 run --insecure-skip-tls-verify test_k6/api_v1_kv_data_write.js
./k6 run --insecure-skip-tls-verify test_k6/api_v1_kv_data_read.js
```

TLS verification is disabled above only for local self-signed certificates.
For a trusted certificate, omit `--insecure-skip-tls-verify`. The authenticated
checks require API access without mandatory mTLS.

The read scripts include auth checks and a default load scenario targeting 1,000
requests/s for 30 seconds. They fail on dropped iterations, over 1% failed
requests, or less than 99% successful checks. Adjust the rate and duration with
`RATE` and `DURATION`; adjust the load generator capacity with
`PREALLOCATED_VUS` and `MAX_VUS`. Run one script at a time when measuring
per-endpoint throughput.
